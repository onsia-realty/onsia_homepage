## 1. 개요

전국 법원경매 물건을 수집(크롤링)해 저장하고, 공개 목록/상세 페이지와 관리자 CRUD로 보여주던 기능.

- 공개 URL: `/auctions` (목록), `/auctions/[id]` (상세)
- 관리자 URL: `/admin/auctions`, `/admin/auctions/new`, `/admin/auctions/[id]/edit`
- 데이터 저장소가 **두 가지**가 공존했다 (마이그레이션 중간 상태).
  1. **Prisma(PostgreSQL, `site` 스키마)** – `AuctionItem` 등 5개 모델. 관리자 CRUD(`/api/auctions`)가 사용.
  2. **Supabase 별도 프로젝트** – `auctions`, `auction_schedules`, `auction_rights`, `auction_analysis` 테이블. 공개 페이지(`/api/auctions-supabase`, 상세 SSR)와 크롤러 저장이 사용.
- 제거 후 `/auctions*`는 `next.config.ts`의 `redirects()`로 `/`에 301.

## 2. 화면 / 기능

### 2.1 공개 목록 `/auctions` (클라이언트 컴포넌트)
- 히어로 + 검색/필터 카드(GlassCard), 다크 그라데이션 배경, framer-motion 등장 애니메이션.
- 필터: 검색어(주소·사건번호·법원명), 지역(시도 17개), 물건종류(APARTMENT/VILLA/OFFICETEL/HOUSE/COMMERCIAL/LAND/FACTORY/BUILDING), 상태(SCHEDULED/BIDDING/SUCCESSFUL/FAILED).
- 활성 필터 칩 표시 + 개별 제거 + 전체 초기화.
- 데이터: `GET /api/auctions-supabase?page&limit=12&search&city&itemType&status`.
- 그리드(1/2/3/4열) + 스켈레톤 로딩 + 빈 상태 + 페이지네이션(현재±2, 처음/끝, `...`).
- 카드(`AuctionCard`): 대표사진, 상태 배지, 회차, 주의(hasRisk) 배지, D-day, 감정가(취소선)/최저가/최저가율, 매각기일, 주소, 면적.
- `layout.tsx`: SEO 메타데이터 + JSON-LD(BreadcrumbList, WebPage, ItemList). OG 이미지 `/og-auctions.png`.

### 2.2 공개 상세 `/auctions/[id]` (서버 컴포넌트 + 클라이언트)
- `page.tsx`: Supabase에서 `auctions` + `auction_schedules` + `auction_rights` + `auction_analysis`를 조인 조회 후 `AuctionDetailClient`가 기대하는 camelCase 형태로 변환. `generateMetadata`로 사건번호·주소 타이틀.
  - 변환 헬퍼: `mapPropertyType`(한글→코드), `mapStatus`(ACTIVE→SCHEDULED, SOLD→SUCCESSFUL…), `mapResult`(유찰/매각/취하/변경), `extractOwner/Debtor/Creditor`(등기내역에서 소유권이전·임의경매 신청자 추출).
  - `images`는 문자열 배열과 `{url,type,alt,order}` 객체 배열 모두 지원(두인경매 포맷).
- `AuctionDetailClient.tsx` 섹션 구성:
  1. 히어로 카드: 메인 이미지 + 썸네일(최대 5장), 상태/회차/주의/D-day 배지, 사건번호·법원, 주소, 물건 태그, 감정가/최저가/최저가율, 매각기일·보증금, 공유/관심등록 버튼(동작 미구현).
  2. 기본정보 테이블(모바일 그리드 / 데스크탑 table): 소재지, 물건종류, 입찰회차, 상태, 대지·건물면적(㎡/평), 소유자·채무자·채권자, 감정가·최저가·보증금, 말소기준일, 배당요구종기, 조회수.
  3. 물건현황: 건물 정보, 편의시설(JSON 배열), 주변환경, 교통, 근린시설, 위치 특이사항.
  4. 권리분석 `RightsAnalysis`: 말소기준일, 위험 경고, 등기내역 테이블(갑구/을구, 순위, 접수일, 목적, 권리자, 채권액, 말소기준/소멸 여부).
  5. 임차인현황 `TenantStatus`: 대항력 있는 임차인 수, 전입·확정일자·배당요구·보증금·월세.
  6. 입찰내역 `BidHistory`: 회차별 최저가·감정가 대비율·결과(유찰/낙찰/취하/연기)·낙찰가·응찰자수.
  7. 사이드바: `AIBidAnalysis`(규칙 기반 "AI" 분석), `RealPriceSection`(주변 시세 비교 → 실거래가 문서 참고), 당사자 정보, `ExternalLinks`.
- `AIBidAnalysis` 로직(실제 AI 호출 없음, 순수 휴리스틱):
  - 예상 시세 = 감정가 × 1.1, 시세 대비 할인율 계산.
  - 추천 입찰가: 최저가 ~ 최저가×1.1(첫 기일은 ×1.15). 유찰 횟수별 멘트, confidence(high/medium/low).
  - 위험 요소(hasRisk, 임차인, 최저가율<50%, 토지/공장), 기회 요소(할인율>30%, 유찰+권리 깨끗, 최저가율 60~80%).
  - 최종 verdict 4단계. 법원 주소/전화 하드코딩 테이블(`COURT_ADDRESSES`) + 네이버/카카오맵 링크.
- `ExternalLinks`: `generateCourtLinks()`로 대법원 사건내역/기일내역/문건송달/현황조사서/감정평가서/매각물건명세서 링크, 인터넷등기소, 국토부 실거래가, 토지이음(PNU 있을 때), 네이버지도/카카오맵/네이버부동산/호갱노노.

### 2.3 관리자 `/admin/auctions`
- 목록: 검색(사건번호·주소), 페이지네이션, 상태/종류 라벨, 보기/수정/삭제(확인 모달). `GET /api/auctions`, `DELETE /api/auctions/[id]`.
- 등록 `new` / 수정 `[id]/edit` (동일 폼, 수정은 `GET /api/auctions/[id]`로 프리필 후 `PUT`):
  - 섹션: 기본 정보(사건번호*, 법원코드 select, 주소, 상세주소, 시도, 시군구, 물건종류, 층, 건물면적, 대지면적) / 가격 정보(감정가, 최저가, 최저가율, 보증금) / 일정 정보(매각기일, 시간, 회차, 배당요구종기) / 권리분석(말소기준일, 위험 여부, 위험 메모) + 등기내역 반복 행 / 임차인 현황 반복 행 / 이미지 URL 반복 행 / 상태·추천(featured).
  - 관리자 폼의 법원코드 목록(`1101` 서울중앙 등)은 `src/lib/court-auction.ts`의 `COURT_CODES`(`1110` 서울중앙 등)와 **불일치**했음(알려진 이슈).

### 2.4 마이페이지 연동
- `Favorite`/`ViewHistory` 모델에 `itemType = AUCTION`, `auctionId`가 있었고 `/api/user/favorites`, `/api/user/history`가 `auction: {id, caseNumber, address}`를 include해 반환.
- `src/app/mypage/page.tsx`는 `item.auction`이 있으면 `/auctions/{id}`로 링크했음. 제거 후에는 링크 없이 주소만 표시(DB·API는 그대로).

## 5. API 명세

### `GET /api/auctions` (Prisma)
- Query: `page`(1), `limit`(12), `search`, `city`, `district`, `itemType`(AuctionItemType), `status`(AuctionStatus), `minPrice`, `maxPrice`(최저가 기준 BigInt), `featured=true`
- 정렬: featured desc → saleDate asc → createdAt desc. 대표사진 1장(PHOTO) + `_count.registers/tenants` 포함.
- Response: `{ items: AuctionItem[](BigInt→string), pagination: { page, limit, total, totalPages } }`

### `POST /api/auctions` (Prisma 등록) / `PUT /api/auctions/[id]`
- Body(camelCase): `caseNumber*, caseNumberFull, courtCode, courtName, pnu, address*, addressDetail, city*, district*, itemType, landArea, buildingArea, floor, appraisalPrice*, minimumPrice*, minimumRate, deposit, saleDate, saleTime, bidCount, bidEndDate, referenceDate, hasRisk, riskNote, owner, debtor, creditor, status, featured, seoTitle, seoDescription, registers[], tenants[], images[]`
  - `registers[]`: `{ registerType, registerNo, receiptDate, purpose, rightHolder, claimAmount, isReference, willExpire, note }`
  - `tenants[]`: `{ tenantName, hasPriority, occupiedPart, moveInDate, fixedDate, hasBidRequest, deposit, monthlyRent, analysis, note }`
  - `images[]`: `{ imageType(PHOTO|SURVEY|APPRAISAL|REGISTER|OTHER), url, originalUrl, alt, order }`
- PUT은 registers/tenants/images를 `deleteMany` 후 재생성(트랜잭션). 응답 201/200에 생성된 레코드(BigInt 문자열화).

### `GET /api/auctions/[id]` (Prisma) – bids(round desc), registers(receiptDate asc), tenants, images(order asc) 포함, viewCount +1.
### `DELETE /api/auctions/[id]` → `{ success: true }` (관계는 Cascade).

### `GET /api/auctions-supabase` (공개 목록)
- Query: `page, limit, search, city(sido eq), itemType(APARTMENT→아파트… ilike), status(SCHEDULED/BIDDING→ACTIVE, SUCCESSFUL→SOLD, FAILED)`
- 항상 주거·상업용 `property_type` ilike OR 필터 적용, `sale_date asc`.
- Response item: `{ id, caseNumber, courtName, address, district, city, itemType(한글), buildingArea, landArea, exclusiveArea, appraisalPrice, minimumPrice, minimumRate, saleDate, bidCount, status, hasRisk:false, referenceDate(dividend_end_date), images[{url,alt}] }`

### `GET /api/auctions-supabase/[id]` – 상세 + `bids[]`(schedules), `registers[]`(rights), `analysis{referenceDate, hasRisk, riskNote, tenantInfo, totalClaim, expectedDividend, investmentGrade, riskLevel}`, `tenants`(= tenant_info).

### `GET /api/court/[type]?courtCode|courtName&caseNumber&raw=true`
- type: `caseDetail | schedule | property | survey | appraisal | saleStatement | documents`
- Response: `{ success, type, typeLabel, courtCode, caseNumber, cached, courtUrl, data(raw면 HTML), dataLength, fetchedAt }`
- `POST` 동일 파라미터(body) → `text/html` 그대로 반환(iframe용).

### `GET /api/crawler?courtCode|courtName&caseNumber` → `{ success, data: AuctionCrawlData, error, source, fetchedAt }`
### `POST /api/crawler` (헤더 `Authorization: Bearer <CRAWLER_API_KEY>`)
- Body: `{ courtCode|courtName, caseNumber }` 또는 `{ caseNumbers: [{courtCode|courtName, caseNumber}] }`
- Response: `{ success, auctionId, error, savedAt }` / 일괄: `{ total, success, failed, results[] }`

### 크롤러 핵심 타입 (`court-crawler-service.ts`)
```ts
interface AuctionCrawlData {
  caseDetail: { caseNumber; courtCode; courtName; caseType; status; creditor?; debtor?; claimAmount?; registrationDate? };
  properties: { itemNumber; propertyType; address; addressRoad?; landArea?; buildingArea?; exclusiveArea?; appraisalPrice?; minimumPrice?; remarks? }[];
  schedules:  { round; saleDate; saleTime?; location?; minimumPrice?; result?; bidCount?; winningBid? }[];
  rights:     { registerType; registerNo?; receiptDate?; purpose?; rightHolder?; claimAmount?; isReference; willExpire; note? }[];
  tenants:    { name?; occupiedPart; moveInDate?; fixedDate?; deposit?; monthlyRent?; hasPriority; bidRequest }[];
  images: string[];
}
```
- 대법원 URL 파라미터: `jiwonCd`(법원코드), `saession`(타경=3), `srnoChamCdNm`(사건종류 첫 글자), `dession`(연도), `saession3`(번호). 엔드포인트 예: `RetrieveRealEstCaramInf.laf`(사건내역), `RetrieveSaleSchdInqSaleList.laf`(기일), `RetrieveRealEstStsInvstInqList.laf`(현황조사), `RetrieveRealEstApslJdgmInqList.laf`(감정평가), `RetrieveRealEstSaleStmtInqList.laf`(매각물건명세), `RetrieveSendOfcDcmtInqList.laf`(문건송달).

## 6. DB 모델

### 6.1 Prisma (`prisma/schema.prisma`, `@@schema("site")`) — **스키마는 삭제하지 않았음**
- `AuctionItem` (`auction_items`): 사건/법원(caseNumber unique, caseNumberFull, courtCode, courtName, pnu), 주소(address, addressDetail, city, district), 물건(itemType enum, landArea, buildingArea, floor, totalFloors, buildingStructure, buildingUsage, landUseZone), 가격(appraisalPrice BigInt, minimumPrice BigInt, minimumRate, deposit, landAppraisalPrice, buildingAppraisalPrice, realPrice), 감정(appraisalOrg, appraisalDate, preservationDate, approvalDate), 일정(saleDate, saleTime, bidCount, bidEndDate), 권리(referenceDate, hasRisk, riskNote), 당사자(owner, debtor, creditor), 현황(surroundings, transportation, nearbyFacilities, heatingType, facilities JSON문자열, locationNote), 외부(buildingInfo, naverComplexId), SEO(seoTitle, seoDescription), 메타(status enum, featured, viewCount, inquiryCount, createdAt, updatedAt). 인덱스: `[status, saleDate]`, `[city, district]`, `[itemType]`, `[pnu]`.
- `AuctionBid` (`auction_bids`): round, bidDate, minimumPrice, result(AuctionBidResult), winningPrice, bidderCount.
- `AuctionRegister` (`auction_registers`): registerType, registerNo, receiptDate, purpose, rightHolder, claimAmount, isReference, willExpire(기본 true), note.
- `AuctionTenant` (`auction_tenants`): tenantName, hasPriority, occupiedPart, moveInDate, fixedDate, hasBidRequest, deposit, monthlyRent, analysis, note.
- `AuctionImage` (`auction_item_images`): imageType(AuctionImageType), url, originalUrl, alt, order(`sort_order`).
- 공용 모델의 경매 필드: `Favorite.auctionId`, `ViewHistory.auctionId`(둘 다 `AuctionItem?` 관계, Cascade), `FavoriteType.AUCTION`.
- enum: `AuctionItemType{APARTMENT,VILLA,OFFICETEL,HOUSE,COMMERCIAL,LAND,FACTORY,BUILDING,OTHER}`, `AuctionStatus{SCHEDULED,BIDDING,SUCCESSFUL,FAILED,WITHDRAWN,CANCELED}`, `AuctionBidResult{FAILED,SUCCESSFUL,WITHDRAWN,POSTPONED}`, `AuctionImageType{PHOTO,SURVEY,APPRAISAL,REGISTER,OTHER}`.

### 6.2 Supabase (`docs/supabase-auction-schema.sql`)
- `auctions`: court_code, court_name, case_number, case_year, item_number, property_type(한글), address, address_road, sido, sigungu, dong, land_area, building_area, exclusive_area, appraisal_price, minimum_price, deposit_amount, bid_count, case_receipt_date, auction_start_date, dividend_end_date, sale_date, sale_place, status(ACTIVE/SOLD/FAILED/CANCELED/POSTPONED), bid_method, claim_amount, note, images JSONB, source_url, crawled_at; 추가 컬럼 owner/debtor/creditor(`scripts/add-party-columns.sql`). UNIQUE(court_code, case_number, item_number).
- `auction_schedules`: schedule_date, schedule_type, schedule_place, minimum_price, result, sold_price.
- `auction_documents`: doc_type(APPRAISAL/SURVEY/SALE_STATEMENT), doc_url, doc_content JSONB. (코드에서 미사용)
- `auction_rights`: register_type, register_no, receipt_date, purpose, right_holder, claim_amount, is_reference, will_expire, note.
- `auction_analysis`: reference_date, has_risk, risk_note, tenant_info JSONB, total_claim, expected_dividend, ai_analysis JSONB, investment_grade, risk_level. UNIQUE(auction_id).
- `court_codes`: code, name, region.
