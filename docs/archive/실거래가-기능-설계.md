## 1. 개요

국토교통부(MOLIT) 공공데이터포털 실거래가 API를 바탕으로

1. **`/market` "AI 부동산시세" 페이지** – 시/군/구·물건종류·기간을 고르면 거래 내역·통계를 카카오맵 위에 아파트별 마커로 보여주던 풀스크린 지도 화면.
2. **경매 상세의 "주변 시세 비교" 카드** (`RealPriceSection`) – 같은 통계 API로 감정가/최저가의 평당가를 지역 평균과 비교.
3. **청약 상세의 "주변 시세 비교"** (`/api/subscriptions/[id]/compare`) – **유지됨**. 별도 클라이언트(`realPriceApi.ts`) 사용.

제거 후 `/market*`은 `next.config.ts` `redirects()`로 `/`에 301. 1·2번과 그 API/라이브러리는 삭제, 3번은 그대로.

실거래가 코드 계통이 **둘**로 나뉘어 있었다는 점이 핵심:

| 계통 | 파일 | 사용처 | 상태 |
|---|---|---|---|
| A. 시장 페이지용 | `src/lib/real-estate-api.ts` + `src/lib/lawd-codes.ts` + `/api/real-price*` | `/market`, `RealPriceSection` | **삭제** |
| B. 청약 비교용 | `src/lib/realPriceApi.ts` | `/api/subscriptions/[id]/compare` | **유지** |

## 2. 화면 / 기능

### 2.1 `/market` (클라이언트 컴포넌트, h-screen 풀스크린)
- 상단 바: 로고, 지역 선택 버튼(시도 › 시군구 드롭다운, `getSidoList/getSigunguList`), 기간 선택(1/3/6/12개월), 통계 요약(평균가·평당가·거래건수), 경매 페이지 링크.
- 좌측 패널(접기 가능): 아파트명 검색, 정렬(평균가/이름/거래건수), 아파트별 그룹 목록(평균가·최저~최고·건수·건축년도·동).
- 지도(`KakaoMap`): 아파트별 마커(최대 60개, `type:'apartment'`, 가격·평수 라벨), 마커 클릭 시 하단에 선택 아파트 상세(거래 내역 리스트 + 경매 유도 배너).
- 데이터: `GET /api/real-price` + `GET /api/real-price/stats`를 `Promise.all`로 동시 호출.
- 좌표: 실거래 API에는 좌표가 없어서 **서울 25개 구 중심 좌표 테이블(`DISTRICT_COORDS`)에 ±0.009도 랜덤 오프셋**을 더해 마커를 뿌림(실제 위치 아님 – 알려진 이슈).
- 초기값: 서울특별시 강남구, 아파트, 3개월. 물건종류 선택 UI는 있으나 기본 '아파트'.
- `layout.tsx`: SEO 메타(타이틀 "AI 부동산시세 - 서울 아파트 실거래가 조회") + JSON-LD(BreadcrumbList, WebPage, Organization 참조). OG `/og-market.png`.
- `/market/map/page.tsx`: `/market`으로 `redirect()`만 하는 잔재.

### 2.2 `src/components/market/` (초기 버전 UI, 마지막 `/market`에서는 미사용)
- `SearchForm.tsx`: 시도/시군구 select + 물건종류 버튼 → `onSearch(sido, sigungu, propertyType)`.
- `StatsCard.tsx`: 평균가·평당가·최고·최저·건수 카드.
- `TransactionTable.tsx`: 거래 테이블(거래일, 단지, 동, 면적/평, 층, 금액, 평당가, 건축년도), 접기/펼치기.

### 2.3 `src/components/auction/RealPriceSection.tsx` (경매 상세 사이드바)
- props: `sido, sigungu, propertyType(한글), appraisalPrice, minimumPrice, area?`
- `GET /api/real-price/stats?...&months=6` 호출 → `stats.avgPricePerPyeong`과 감정가/최저가의 평당가(만원) 비교해 ±% 표시, 최근 거래 몇 건, `/market` 링크.
- 로딩/에러/데이터 없음 상태 분기.

### 2.4 청약 상세 "주변 시세 비교" (유지)
- `src/app/subscriptions/[id]/SubscriptionDetailClient.tsx`가 `GET /api/subscriptions/{id}/compare?address=&pricePerPyeong=` 호출 → `compare.complexes[]`, `compare.summary.avgPricePerPyeong` 렌더. 카카오맵(`KakaoMap`)도 여기서 사용 중이므로 컴포넌트 유지.

## 3. 데이터 흐름

```
계통 A (삭제됨)
  /market, RealPriceSection
      │ fetch
      ▼
  GET /api/real-price            GET /api/real-price/stats
      │                                │
      ▼                                ▼
  getRecentTransactions()  ──▶  getRealPriceStats() = getRecentTransactions() + calculateStats()
      │ (lib/real-estate-api.ts)
      ├─ USE_MOCK_DATA === true  →  하드코딩 Mock(강남·송파·서초·용인 처인) 기간 필터 후 반환   ← 실제 배포 상태
      └─ false                   →  getLawdCode(sido, sigungu) (lib/lawd-codes.ts)
                                    → 월별 YYYYMM 목록 → 3개월씩 Promise.all
                                    → MOLIT XML API fetch → parseTransactionXml (정규식)

계통 B (유지)
  SubscriptionDetailClient ─▶ GET /api/subscriptions/[id]/compare
      → parseAddress(주소→시도/시군구) → extractLawdCd(주소→5자리, 부분 매핑)
      → getRecentRealPrices(lawdCd, 6)  (lib/realPriceApi.ts, data.go.kr JSON API, 월별 순차 + 100ms 딜레이)
      → 단지별 그룹화 → 분양 평당가 대비 차이 계산
```

캐싱: 둘 다 **서버 캐시 없음**. `fetch`에 `next.revalidate`도 없음. 계통 A는 Mock이라 사실상 네트워크 호출이 없었다.

### 4.3 `realPriceApi.ts` ↔ `compare` 의존 관계 (유지 코드)
```ts
// src/lib/realPriceApi.ts — export 목록
getApartmentRealPrice({ lawdCd, dealYmd, numOfRows? }): Promise<RealPriceData[]>  // 단월 조회
getRecentRealPrices(lawdCd, months=6): Promise<RealPriceData[]>                     // 월별 순차 호출
extractRegionCode(address): string | null       // 시도 2자리
extractLawdCd(address): string | null           // 5자리(부분 매핑, 없으면 "{시도}000" 폴백)
parsePrice("82,000") → 82000 (만원)
sqmToPyeong(sqm), calculatePricePerPyeong(price, area)
interface RealPriceData { aptNm, dealAmount, dealYear, dealMonth, dealDay, buildYear, excluUseAr, floor, umdNm, jibun, sggCd, aptDong?, dealingGbn?, estateAgentSggNm?, rgstDate? }
```
compare 라우트가 쓰는 것: `getRecentRealPrices, extractLawdCd, parsePrice, calculatePricePerPyeong, RealPriceData`.
`extractLawdCd`의 매핑은 서울 4구·경기 일부·인천 서구·부산 남구·대전 서구뿐이라 그 외 지역은 `"41000"` 같은 폴백 코드로 호출돼 빈 결과가 나온다. 전국 커버가 필요하면 삭제된 `lawd-codes.ts`의 테이블을 여기로 합치면 된다.

## 5. API 명세 (삭제된 것)

### `GET /api/real-price`
- `?list=sido` → `{ success, data: string[] }` 시도 목록
- `?list=<시도명>` → 시군구 목록
- `?sido&sigungu&propertyType(기본 아파트)&months(기본 6)`
- Response:
```json
{ "success": true, "data": { "sido", "sigungu", "propertyType", "months", "totalCount",
  "transactions": [{ "dealDate":"YYYYMMDD","dealYear","dealMonth","dealDay","buildingName","dong",
                     "area":84.9,"floor":"12","price":148000,"pricePerPyeong":5760,"buildYear":"2020",
                     "priceFormatted":"14억 8,000만원","pyeong":25.7,"pricePerPyeongFormatted":"5,760만원" }] } }
```
- 400: sido/sigungu 누락. 500: `{ success:false, error }`.

### `GET /api/real-price/stats` (같은 쿼리)
```json
{ "success": true, "data": { "sido","sigungu","propertyType","months",
  "stats": { "avgPrice","avgPricePerPyeong","maxPrice","minPrice","totalCount",
             "recentTransactions":[...최근 10건],
             "avgPriceFormatted","avgPricePerPyeongFormatted","maxPriceFormatted","minPriceFormatted" } } }
```

### `src/lib/real-estate-api.ts` 주요 시그니처
```ts
interface RealTransaction { dealDate; dealYear; dealMonth; dealDay; buildingName; dong; area; floor; price(만원); pricePerPyeong; buildYear }
interface PriceStats { avgPrice; avgPricePerPyeong; maxPrice; minPrice; totalCount; recentTransactions: RealTransaction[] }
mapPropertyTypeToApi(propertyType): '아파트'|'연립다세대'|'오피스텔'|'상업업무용'|'공장창고'|null
getRealTransactionPrice(lawdCd, dealYmd, propertyType): Promise<RealTransaction[]>   // 단월, XML 파싱
getRecentTransactions(sido, sigungu, propertyType, months=6): Promise<RealTransaction[]>
calculateStats(transactions): PriceStats
getRealPriceStats(sido, sigungu, propertyType, months=6): Promise<PriceStats>
formatPrice(만원) → "N억 N만원" / sqmToPyeong(㎡)
```
- `PROPERTY_TYPE_MAP`: 아파트→아파트, 다세대/연립/빌라/다가구→연립다세대, 오피스텔, 근린시설/상가/근린상가→상업업무용, 공장/창고→공장창고.
- XML 파싱은 `<item>…</item>` 정규식 + 필드별 태그 추출(아파트/연립/오피스텔 태그명 차이를 OR로 처리). 에러는 `<returnReasonCode>`≠0 검사.

### `src/lib/lawd-codes.ts`
```ts
SEOUL_CODES, GYEONGGI_CODES, METRO_CODES(광역시별), SIDO_CODES
getLawdCode(sido, sigungu): string | null
getRegionName(lawdCode): { sido, sigungu } | null
getSidoList(): string[]   getSigunguList(sido): string[]
```

## 8. 알려진 이슈 / TODO

1. `USE_MOCK_DATA = true` 하드코딩 → `/market`은 실제 API를 호출하지 않았고 강남·송파·서초·용인 처인구만 데이터가 있었음. 실제 연동 시 엔드포인트를 data.go.kr 신규 주소로 교체 필요.
2. 마커 좌표는 구 중심 + 랜덤 오프셋(가짜 위치). 실제 위치는 단지명/지번 → 카카오 로컬 API 지오코딩이 필요(`src/lib/geocoding.ts` 존재, 청약 크롤러가 사용).
3. `realPriceApi.ts`의 `extractLawdCd` 지역 매핑이 매우 부분적이며 같은 키('서구')가 인천·대전에 중복 정의돼 뒤 항목이 덮어씀. 전국 테이블은 삭제된 `lawd-codes.ts` 참고.
4. `realPriceApi.getRecentRealPrices`는 월별 순차 호출(6회 + 100ms 딜레이) + 캐시 없음 → 청약 상세 로딩이 느릴 수 있음. `unstable_cache`/`revalidate` 또는 DB 캐시 테이블 권장.
5. `realPriceApi.ts`에 기존 tsc 에러 1건 있음(기능 제거 전부터 존재, 빌드는 `ignoreBuildErrors`로 통과).
6. 계통 A XML 파서는 정규식 기반이라 태그 변경에 취약.
7. `src/components/market/*`는 마지막 `/market`에서 이미 미사용(초기 버전 잔재).
